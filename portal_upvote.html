Mainnet note The Abstract Session Key Policy Registry requires a security review before session keys can call contracts on mainnet. If the upvote contract (0x3b50de27…ce2a) is not yet whitelisted, the daily upvote will revert silently. Everything else (session creation, storage) still works.
How it works
  1. Select your Abstract wallet below.
  2. A new session key is generated locally — your owner key never leaves the browser.
  3. You sign one on-chain transaction that registers the session key, scoped only to upvote(uint256) on 0x3b50de27…ce2a.
  4. The session private key is encrypted with AES-256-EAX and stored server-side. Only the agent decrypts it at runtime — never committed to git.
  5. Each day at 09:00 UTC the agent scrapes the Portal, picks the least-recently-upvoted app, and submits the transaction autonomously.
Requirements Make sure SESSION_KEY_ENCRYPTION_KEY is set in Railway env vars before authorizing (generate: python -c "import secrets; print(secrets.token_hex(32))").
